# 数据处理流程规范

> 本文档定义了中税云检系统中数据处理的标准流程和质量控制要求。

## 🔄 标准处理流水线

```
原始数据采集 → 数据清洗 → 格式标准化 → 敏感信息脱敏 → 质量校验 → 入库存储
```

---

## 第一步：原始数据采集

### 支持的数据源

| 数据源类型 | 支持格式 | 采集方式 |
|-----------|---------|---------|
| 金税系统 | XML/JSON/API | 接口对接 |
| 电子税务局 | CSV/PDF | 定时下载 |
| 企业申报表 | Excel/Word | 手动导入 |
| 第三方平台 | API/Webhook | 实时推送 |

### 采集注意事项

- ✅ 使用加密通道传输（HTTPS/TLS 1.3+）
- ✅ 记录采集日志（时间、来源、条数、哈希值）
- ❌ 明文传输敏感字段
- ❌ 缓存未脱敏的完整数据

---

## 第二步：数据清洗

### 清洗规则清单

```python
CLEANING_RULES = {
    # 空值处理
    'null_handling': {
        'strategy': 'fill_or_drop',
        'numeric_fill': 0,
        'text_fill': '[缺失]',
        'drop_threshold': 0.3,  # 缺失率超30%则丢弃该列
    },
    
    # 格式统一
    'format_standardization': {
        'date': '%Y-%m-%d',           # 统一日期格式
        'amount': '{:.2f}',            # 金额保留两位小数
        'tax_id': r'^\d{18}$',         # 纳税人识别号18位
        'phone': r'^1\d{10}$',         # 手机号11位
    },
    
    # 去重策略
    'deduplication': {
        'keys': ['invoice_id', 'taxpayer_id', 'period'],
        'keep': 'latest',              # 保留最新记录
        'conflict_resolution': 'manual',  # 冲突时人工介入
    },
}
```

---

## 第三步：敏感信息脱敏

### 脱敏优先级矩阵

| 信息类别 | 敏感级别 | 脱敏方法 | 可逆性 |
|---------|---------|---------|-------|
| 身份证号 | 🔴 极高 | 掩码(保留前3后4) | ❌ 不可逆 |
| 手机号码 | 🔴 极高 | 掩码(保留前3后4) | ❌ 不可逆 |
| 银行账号 | 🔴 极高 | 掩码(保留首尾各4位) | ❌ 不可逆 |
| 姓名 | 🟠 高 | 替换为占位符 | ❌ 不可逆 |
| 地址 | 🟠 高 | 模糊化处理 | ❌ 不可逆 |
| 企业全称 | 🟡 中 | 保留简称 | ⚠️ 条件可逆 |
| 金额数值 | 🟢 低 | 保留原值(统计用) | N/A |
| 税率/比例 | 🟢 低 | 保留原值 | N/A |

---

## 第四步：质量校验

### 校验项目清单

```yaml
quality_checks:
  completeness:
    - name: "非空率检查"
      threshold: 95%
      
  consistency:
    - name: "税率范围校验"
      valid_values: [0, 0.03, 0.06, 0.09, 0.13]
      
    - name: "金额关系校验"
      rule: "不含税额 + 税额 = 价税合计"
      
  accuracy:
    - name: "纳税人识别号格式"
      pattern: "^[0-9A-HJ-NPQRTUWXY]{18}$"
```

---

## 第五步：入库存储

### 存储架构

```
├── raw_zone/          # 原始数据区（加密存储）
├── clean_zone/        # 清洗后数据
├── desensitized_zone/ # 脱敏数据区（可共享）
└── archive/           # 归档区
```

*本文档遵循《数据安全法》《个人信息保护法》相关要求*
